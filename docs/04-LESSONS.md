# 复盘（赛道AB · AME-1474《总机》）

挂在 AME-1127 下，给下一次做短片（或任何"长流程渲染"）时先看。

## 1. 交付的成片是旧的 —— 本次最重要的一个坑

- **现象**：`out/zongji.mp4`（上一轮交接下来的）第 137–155 秒是一板**火花塞**，
  而图版 `plates/board-dead-lamp.png` 明明是对的塞孔板。
- **原因**：换过图版之后只重渲了"受影响的分段"，成片却还是用更早的 `seg*.mp4` 拼的。
  成片时间戳比图版新，光看 `ls` 看不出来。
- **判据**（以后固定这么做）：**改了图版或镜头表，就整条重建**；并且**从成片抽帧**与
  `render.py` 现渲一帧对比，两帧不一致 = 成片是旧的。
- 断言只读成片，不读中间产物 —— 中间产物永远是"可能过期的缓存"。

## 2. 颗粒会把码率吃到 72 Mbps

| 设置 | 码率 | 全片 |
| --- | --- | --- |
| σ=9.0 + CRF 18 | 72 Mbps | ~2.7 GB |
| σ=9.0 + CRF 23 | 57.5 Mbps | ~2.2 GB |
| σ=4.5 + CRF 23 + `-maxrate 14M -bufsize 28M` | **9.1 Mbps** | **~350 MB（实测 293 MB）** |

CRF 只保画质、不保体积；逐帧随机噪声对 x264 是纯熵。
**`-maxrate` 必须配 `-bufsize`**，只给前者不生效。

## 3. 我的两条断言本身是错的（比片子错更值得记）

- **"台词要比本镜尾巴响 1.6×"**：台词常常比"尾巴"还长，等于拿台词比台词，
  于是 29 条里 10 条被判"听不见"——片子没问题，尺子有问题。
  改成：台词中位 vs **全片 0.5 s 窗的 25 分位**（真正的安静段），实测 7.4×。
- **"图版右下角锐度比 ≤ 2"**：塞孔板右下天然是一排塞孔，比值 11.9，判"有水印"；
  裁出来放大一看干净得很。改成**绝对锐度 ≤ 3.5**（中值滤波之后这块应该很平），实测最锐 2.77。
- **教训**：判据报错时，先问"是片子错了还是尺子错了"，两边都要有办法验证。
  这次两次都是尺子错，靠"把那一块放大看"定案。

## 4. 一个十八秒不动的镜头等于没有这个镜头

S12 原来是单图 + 1.13 倍慢推，十八秒里画面几乎不变，而这是全片的情绪支点。
加 `dying` 叠加层（亮度三级下台阶 + 台阶口抖两下）之后，"话路一条条退"才看得见。
**判据**：≥10 秒的镜头，时间轴上必须有至少一次可测的亮度或构图变化。

## 5. 派单到"agent 真跑起来"之间有一段黑箱

- 建单 → 状态 `todo` → 并不等于有人接。本次两位评委连续 502/503（TLS 拦截），
  三次都失败在**平台出网**，不是模型。
- 可行的做法：`issue rerun-task <run> --fresh` 重排；仍失败就**换一个本地 runtime 的 agent**。
- 还有一条：**给评委的六帧要真的代表片子**。第一组六帧漏了人物，等于让评委判一个没有人的片子，
  发现后立刻作废重派（AME-1477/1478 → 1479/1480）。
