# 04 — 这一场踩到的坑

写给自己下一次用。每条都带判据，下次照着验，不要靠"我觉得没问题"。

## 1. 交付的成片可能是旧的（本场最大的坑）

**现象**：`out/zongji.mp4` 里 S12 是一板火花塞，而 `plates/board-dead-lamp.png` 明明是对的塞孔板。
**原因**：上一轮换过图版，但只重渲了"以为受影响"的分段；`out/` 里那份成片是用旧 `seg*.mp4`
拼出来的，时间戳比图版新，看不出来。
**判据**：**任何图版/镜头表改动后，必须整条重建**（`bash verify.sh`），不许只重渲某一段。
**发现方式**：从成片抽一帧，和 `render.py` 现渲一帧对比——两帧不一样就说明成片是旧的。
这条已经写进 `verify.py` 的思路里：断言只读成片，不读中间产物。

## 2. 颗粒会把码率吃到失控

| 设置 | 实测码率 | 全片体积 |
| --- | --- | --- |
| 颗粒 σ=9.0 + CRF 18 | **72 Mbps** | ≈ 2.7 GB |
| 颗粒 σ=9.0 + CRF 23 | 57.5 Mbps | ≈ 2.2 GB |
| 颗粒 σ=4.5 + CRF 23 + `-maxrate 14M` | **9.1 Mbps** | ≈ 350 MB |

CRF 只认画质，不认体积；随机噪点对 x264 是纯熵，越细越贵。
**做法**：颗粒降到 σ=4.5（1080p 下仍看得见），CRF 23，另加 `-maxrate 14M -bufsize 28M` 封顶。
`-maxrate` 必须配 `-bufsize`，只给前者不生效。

## 3. 一个十八秒不动的镜头，等于没有这个镜头

S12 原来是单张图版 + 1.13 倍的推镜，十八秒里画面几乎没有变化——而这是全片的情绪支点。
**改法**：加 `dying` 叠加层（亮度分三级下台阶，每个台阶口抖两下），让"话路一条条退"看得见。
**判据**：任何 ≥ 10 秒的镜头，必须在时间轴上有至少一次可测的亮度或构图变化。

## 4. 2:3 的图版裁 16:9，横摇一定会出事（沿用 AME-1435）

横向余量只有 1024−576=448 px 的原图宽度，摇出去就是画外或工具水印。
**做法**：只做 push / static / 纵向小幅 pan，位移 ≤ 0.10 画幅。

## 5. 工具水印不能靠裁（沿用 AME-1466）

裁掉的那 6% 往往就是主体（本片 S16 的红纸就在右下）。**用中值滤波抹掉，再断言梯度。**

## 6. 单源要连"注释"一起管

`story.py` 里 S23 的注释写着"全片 306 秒"，实际是 303——改时长忘了改注。
**判据**：`verify.py` 用正则从注释里读片长，和实测片长比。注释不许说假话。

## 7. 一条命令必须能从空目录跑到成片

`verify.sh` 里的每一步都不能依赖"我本机已经有的东西"：
字体子集在 clone 里没有源字体时打印 SKIP 而**不报错**；图版原件在仓库里；
配音需要网络（`edge-tts`），所以 clone 复验要在联网环境跑，日志里写明。
